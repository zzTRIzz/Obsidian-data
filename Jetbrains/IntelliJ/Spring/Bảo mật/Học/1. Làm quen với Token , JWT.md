Hiểu về Token và JWT là một phần quan trọng trong phát triển ứng dụng web hiện đại, đặc biệt là khi làm việc với xác thực (authentication) và phân quyền (authorization). 

---

### 🔑 **Token là gì?**
- **Định nghĩa**: Token là một chuỗi dữ liệu nhỏ được dùng để xác thực người dùng hoặc ứng dụng, cho phép họ truy cập vào tài nguyên được bảo vệ (API, trang web, dịch vụ, ...).
- **Ví dụ**: Giống như thẻ ra vào (access card) 🪪, bạn chỉ cần đăng nhập một lần, nhận token, và dùng nó cho các yêu cầu sau mà không cần nhập lại username/password.
- **Cách hoạt động**:
  1. Người dùng đăng nhập → server kiểm tra thông tin.
  2. Nếu hợp lệ, server tạo token → gửi về client (trình duyệt/app).
  3. Client lưu token (thường trong `localStorage`, `cookie`, hoặc `sessionStorage`).
  4. Mỗi lần gọi API, client gửi kèm token trong header (thường là `Authorization: Bearer <token>`).
  5. Server kiểm tra token → nếu hợp lệ, cho phép truy cập.

---

### 🛠️ **JWT (JSON Web Token) là gì?**
JWT là một chuẩn mở (RFC 7519) định nghĩa cách tạo token an toàn, nhỏ gọn, và dễ truyền tải giữa các hệ thống.

#### **Cấu trúc JWT**
JWT gồm 3 phần, phân cách bằng dấu `.`:
```
Header.Payload.Signature
```
Ví dụ:
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjMiLCJuYW1lIjoiSm9obiIsImFkbWluIjp0cnVlfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

1. **Header** (Phần đầu):
   - Chứa thông tin về thuật toán mã hóa (`alg`) và loại token (`typ`).
   - Ví dụ:
     ```json
     {
       "alg": "HS256",  // Thuật toán HMAC-SHA256
       "typ": "JWT"     // Loại token là JWT
     }
     ```

2. **Payload** (Phần thân):
   - Chứa dữ liệu (claims) như user ID, tên, quyền hạn, thời gian hết hạn (`exp`), thời gian phát hành (`iat`), ...
   - Ví dụ:
     ```json
     {
       "sub": "123",     // Subject (user ID)
       "name": "John",
       "admin": true,
       "iat": 1516239022  // Issued At (thời gian tạo)
     }
     ```
   - ⚠️ Lưu ý: Payload chỉ được **mã hóa Base64Url**, không phải mã hóa bảo mật → ai cũng có thể đọc được nếu có token.

3. **Signature** (Chữ ký):
   - Tạo bằng cách hash `Header + Payload` kết hợp với **secret key** (chỉ server biết).
   - Công thức:
     ```
     HMACSHA256(base64Url(header) + "." + base64Url(payload), secretKey)
     ```
   - Signature đảm bảo token không bị sửa đổi. Nếu payload bị thay đổi, chữ ký sẽ không khớp → token vô hiệu.

---

### 👀 **JWT có thể giải mã được không?**
- **Có thể đọc** Header và Payload vì chúng chỉ được mã hóa Base64Url (dùng [jwt.io](https://jwt.io) để decode).
- **Không thể giả mạo** Signature nếu không biết `secretKey`.

---

### 🔄 **Khi nào dùng JWT?**
- ✅ **Xác thực (Authentication)**: Sau khi đăng nhập, dùng JWT để truy cập các API/tài nguyên bảo mật.
- 🔄 **Trao đổi dữ liệu an toàn** giữa các microservices.
- 📦 **Stateless**: Không cần lưu session trên server → dễ mở rộng (scalable).

---

### ✅ **Validation vs 🔐 Verification**
- **Validation**: Kiểm tra token có hợp lệ không?
  - Đúng cấu trúc JWT.
  - Có các trường bắt buộc (`exp`, `iat`, ...).
  - Chưa hết hạn (`exp` > thời gian hiện tại).
- **Verification**: Kiểm tra token có đáng tin không?
  - Signature có khớp không? (dùng `secretKey` để kiểm tra).
  - Token có bị thu hồi không? (nếu dùng blacklist/whitelist).

---

### ⚠️ **Lưu ý quan trọng**
1. **Không lưu thông tin nhạy cảm** trong JWT (ví dụ: password) vì Payload có thể đọc được.
2. **Đặt thời gian hết hạn (exp)** ngắn (ví dụ: 1 giờ) để giảm rủi ro token bị đánh cắp.
3. **Dùng HTTPS** để tránh token bị đánh cắp qua man-in-the-middle.
4. **Không dùng JWT cho session dài hạn** → nên dùng **refresh token** để lấy JWT mới.

---

### 📌 **Tóm tắt cần nhớ**
- JWT = Thẻ đăng nhập kỹ thuật số có chữ ký.
- Gồm 3 phần: `Header.Payload.Signature`.
- Payload đọc được nhưng không sửa được nếu không có `secretKey`.
- Dùng cho xác thực, phân quyền, trao đổi dữ liệu stateless.
